# EllowDigital — Organisation Standards

This repository is the shared home for the **EllowDigital organisation profile** and default community-health guidance.

## What lives here

- **[Organisation profile](profile/README.md):** the public overview shown on the EllowDigital organisation page.
- **CONTRIBUTING.md:** contribution and pull-request expectations.
- **CODE_OF_CONDUCT.md:** collaboration standards.
- **SECURITY.md:** private vulnerability-reporting guidance.
- **ACCESSIBILITY.md:** accessibility expectations and reporting guidance.
- **SUPPORT.md:** where to ask questions and request help.
- **PULL_REQUEST_TEMPLATE.md:** a consistent review checklist.
- **.github/ISSUE_TEMPLATE/**: reusable issue forms for repositories that do not provide their own.

## How the defaults work

GitHub can use supported community-health files from this public repository when an EllowDigital repository does not define its own equivalent. Repository-specific guidance takes precedence. Some projects have client, product, regulatory, or operational requirements, so maintainers should add or keep local instructions whenever the shared defaults are not suitable.

## Development and release workflow

1. Create or update changes on the **dev** branch.
2. Open a pull request from **dev** into **main**.
3. Review the content, links, template syntax, and any effect on other repositories.
4. Merge only after review and applicable checks pass.

Do not commit directly to **main** for routine changes. If a repository does not yet have a development branch, establish the branch workflow before making substantial changes.
